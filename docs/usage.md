# 在项目中使用 GuardedPy

这篇手册面向已经安装 GuardedPy、装好项目依赖并保存 DeepSeek 凭据的用户。一次任务启动一个**回合**，其中可以包含多次模型请求和工具操作；一个**会话**保存围绕同一问题展开的多个回合。

## 接入自己的项目

进入项目根目录，激活已装好项目依赖的环境，将 GuardedPy 安装到这个环境，再启动：

```bash
cd /path/to/python-project
source .venv/bin/activate
python -m pip install -e ~/projects/guardedpy
python -m pytest
guardedpy
```

这里沿用 `~/projects/guardedpy` 作为 GuardedPy 源码位置。已有安装可以直接启动；pytest 展示项目当前的测试状态。GuardedPy、测试和获批的 Python 程序使用同一个解释器，缺少依赖或导入失败时，按项目声明在这个环境中安装依赖、修正项目安装方式。

### 项目目录如何识别

启动目录就是项目根目录。源码优先取其中的 `src/`；其余布局通过根目录的普通 Python 模块，或包含 `__init__.py` 的包识别，源码范围取根目录。`conftest.py`、`test_*.py`、`*_test.py` 等测试文件承担测试角色。

测试目录从以下配置中读取。程序按顺序选取一份配置：`pytest.ini` 存在时优先采用，其余文件在包含相应区段时采用。

| 顺序 | 文件 | 区段 |
| --- | --- | --- |
| 1 | `pytest.ini` | `[pytest]` |
| 2 | `pyproject.toml` | `[tool.pytest.ini_options]` |
| 3 | `tox.ini` | `[pytest]` |
| 4 | `setup.cfg` | `[tool:pytest]` |

自定义测试目录通过 `testpaths` 指定。例如，在 `pyproject.toml` 中写入：

```toml
[tool.pytest.ini_options]
testpaths = ["checks/unit", "checks/integration"]
```

`testpaths` 需要列出一个或多个已经存在的项目内目录，使用项目相对路径。上例要求 `checks/unit/` 和 `checks/integration/` 都已存在。

选定配置没有 `testpaths`，或没有找到配置时，先识别根目录的 `tests/`；再查找项目内的 `test_*.py`、`*_test.py`，找到后把根目录作为测试范围，查找时跳过隐藏目录。因此 `src/` 配合 `tests/`、根目录模块配合 `tests/`，以及根目录模块配合 `test_*.py` 都是可用布局。

项目需要同时具备源码和测试布局。出现“无法识别 Python pytest 项目”时，检查启动目录、源码位置、pytest 配置格式及测试目录是否存在。修正后重新启动即可更新识别结果。界面中的 `/doctor` 显示当前项目配置状态。

## 提交任务

在主输入框中说明失败现象、预期行为和需要保留的约束，按 Enter 提交：

```text
分页函数在记录数恰好是页大小整数倍时多返回一个空页。请定位原因并修复，保持函数签名和现有测试预期，完成后运行完整 pytest。
```

终端会陆续显示模型文字、工具执行和测试结果。运行中可以滚动查看已完成的步骤；任务结束后，直接输入下一项要求即可继续当前会话。

### 先分析方案或审查代码

需要先理解实现时，用 `/plan` 提交分析任务；需要查找问题时，用 `/review` 指定审查范围：

```text
/plan 分析分页函数在最后一页边界上的处理，给出修复步骤。
/review pagination.py 的边界条件与测试覆盖
```

省略 `/review` 参数会审查当前项目。这两种模式允许列出文件、读取文本和查看 Git 信息。计划或审查结束后，直接提交修改要求，下一回合进入普通模式。启动新的计划或审查前，等待当前回合结束，或中断它。

## 调整正在进行的工作

### 补充当前任务

Agent 运行时，直接输入补充说明：

```text
保留结果中的元素顺序，空输入仍返回空列表。
```

这条消息加入当前回合，在下一次模型请求前交给模型，用于调整后续操作。

### 安排下一项任务

当前回合正在运行时，用 `/queue` 排队：

```text
/queue 检查分页函数的空输入用例，并解释当前行为。
```

任务按提交顺序逐个执行。当前回合完成或失败后，下一项作为普通回合启动，并使用它开始时的模型设置。

`/goal` 则为下一次从输入框手动启动的回合附加要求。例如，先提交 `/goal 保持公开接口和返回顺序`，再输入具体任务。该回合开始时消耗这个目标；排队任务使用各自提交的任务文本。`/goal clear` 清除尚未使用的目标。

### 停止执行

输入 `/stop`，或在运行时按 `Ctrl+C`、`Esc`，请求中断当前回合并清空任务队列。等待审批的回合会直接结束；已经启动的同步 pytest 或 Python 程序先返回或超时，再完成中断。

已经写入的修改保留在项目目录。等终端显示中断结果后，检查文件，再提交后续任务。

## 处理审批

模型请求删除文件或运行项目内的 Python 程序时，界面会列出操作、目标路径和参数。选择“本次允许”执行这一条调用，或选择“拒绝”将决定交给模型。后续需要审批的调用会分别询问。

读取、允许范围内的补丁、pytest 和只读 Git 查询按工具规则执行。pytest 会加载项目测试、配置和插件；pytest 与获批的 Python 程序都以当前用户权限执行，并继承当前环境。`/permissions` 可以查看工具权限摘要。

## 核对测试与改动

通过补丁或删除工具改动文件后，Agent 需要在该回合通过完整 pytest。若最终显示“本轮未完成：修改后尚未通过完整 pytest 验证”，先阅读最后的测试输出，再提交后续任务：

```text
检查当前修改，运行完整 pytest，处理仍然失败的用例，并说明最终结果。
```

`/tests` 用于你自己查看完整 pytest 的结果分类；它的输出留在本地检查中，不进入模型上下文，也不改变 Agent 回合的验证状态。要让模型利用测试反馈继续工作，直接提交上面的任务。

`/diff` 显示 Git 是否存在未暂存的已跟踪文件差异。查看具体补丁时，在另一个终端进入项目，或输入 `/exit` 退出后运行：

```bash
git status --short
git diff
git diff --cached
```

这三条命令分别显示文件状态、未暂存差异和已暂存差异。新增文件会出现在状态列表中，可以直接打开阅读。

测试出现收集或导入错误时，在项目虚拟环境中运行 `python -m pytest` 查看完整输出，处理报错后再提交任务。模型连接失败时，检查凭据和终端到 `https://api.deepseek.com` 的连接，再重新提交任务。

## 继续和管理会话

在交互终端中，不带任务参数运行 `guardedpy` 会打开当前项目最近的会话；首次运行会创建一条会话。带初始任务启动则创建新会话：

```bash
guardedpy "解释分页函数如何处理最后一页"
```

| 操作 | 步骤与结果 |
| --- | --- |
| 新建 | 输入 `/new`；有回合正在运行时，确认停止并新建，等待中断完成后切换 |
| 选择 | 回合结束后输入 `/conversations`，从列表选择会话 |
| 删除 | 回合结束后输入 `/delete`，删除当前记录并打开其余会话中最近更新的一条；每个项目至少保留一条会话 |
| 退出 | 输入 `/exit`；有回合正在运行时，确认中断并退出 |

历史会话可以继续阅读和追问。重新启动后，模型依据近期消息与回合摘要恢复背景，继续处理文件时重新读取当前内容。删除会话只处理对话记录，项目中的修改仍然保留。

### 会话与设置保存在哪里

默认状态目录是 `~/.local/state/guardedpy/`。其中 `local-state.yaml` 记录最近选中的项目，各项目有自己的子目录：

```text
~/.local/state/guardedpy/
├── local-state.yaml
└── <项目路径哈希>/
    ├── harness.yaml
    └── conversations.sqlite3
```

项目子目录名取解析后的项目绝对路径的 SHA-256 前 16 个十六进制字符。`harness.yaml` 保存项目布局、解释器和模型选项等执行设置，`conversations.sqlite3` 保存可见消息和回合结果摘要。程序每次启动重新识别布局，保留已经选择的模型与思考强度。

更换状态位置时，在项目终端设置 `XDG_STATE_HOME` 后启动：

```bash
export XDG_STATE_HOME="$HOME/.guardedpy-state"
mkdir -p "$XDG_STATE_HOME"
guardedpy
```

这个例子使用 `~/.guardedpy-state/guardedpy/`。以后从设置了相同变量的终端启动，就能使用这一位置的记录；原目录继续保留。项目移动到新的绝对路径时，也会得到新的项目状态子目录，原位置的设置与会话留在原子目录。

## 调整模型与凭据

输入 `/model` 或点击界面下方的模型名称打开选择器；输入 `/effort` 或点击强度名称调整思考强度。

| 设置 | 可选值 | 默认值 |
| --- | --- | --- |
| 模型 | `deepseek-v4-flash`、`deepseek-v4-pro` | `deepseek-v4-flash` |
| 思考强度 | `high`、`max` | `high` |

思考功能保持开启，强度值随请求传给 DeepSeek。选择立即保存为当前项目的默认值，在下一个回合开始时使用。正在运行的回合沿用启动时的模型与强度，排队任务在开始执行时取得设置。同一项目的各个会话共用这组默认值。

更新 API Key 时，输入 `/credentials`，在掩码输入框填写新值并选择“更新”。清除凭据时，在同一窗口选择“清除”，再选择“确认清除”。“已配置”表示存在凭据记录，认证与网络连接的结果在实际请求中显示。

凭据位于系统 keyring 的服务 `guardedpy`、用户名 `deepseek-api-key` 下，同一用户环境中的项目共用这个条目，独立于项目路径和状态目录。每次模型请求发起时读取 keyring，因此更新或清除会影响后续请求；已经发出的请求使用此前取得的凭据。

## 命令与输入

输入 `/` 或点击输入框旁的 `＋` 打开命令选择器。用方向键浏览，按 Enter 将选中的命令放入输入框，再补充参数并提交。输入框已经是完整命令名时，Enter 直接执行。

| 用途 | 命令 |
| --- | --- |
| 计划、审查 | `/plan <任务>`、`/review [路径或要求]` |
| 下一次手动任务的目标 | `/goal <目标>`、`/goal clear` |
| 排队、停止 | `/queue <任务>`、`/stop` |
| 会话管理 | `/new`、`/conversations`、`/delete` |
| 本地检查 | `/tests`、`/diff`、`/doctor`、`/permissions` |
| 凭据、模型、思考强度 | `/credentials`、`/model`、`/effort` |
| 帮助、退出 | `/help`、`/exit` |

| 按键 | 操作 |
| --- | --- |
| Enter | 提交输入；浏览命令候选时填入所选命令 |
| Shift+Enter 或 Ctrl+J | 换行 |
| ↑ / ↓ | 在命令选择器中移动 |
| Ctrl+C 或 Esc | 运行时请求中断 |
| Ctrl+Shift+C | 复制当前界面的会话文本 |

## 从管道或脚本运行

标准输入、标准输出只要有一端不是交互终端，GuardedPy 就使用纯文本模式。它使用当前用户已经保存在系统 keyring 中的 DeepSeek 凭据。从项目环境运行：

```bash
cd /path/to/python-project
source .venv/bin/activate
guardedpy "/review pagination.py 的边界条件" </dev/null
```

每次纯文本调用创建新会话。命令行任务参数先执行，然后逐行读取标准输入；每个非空行作为下一条任务或命令，前一条结束后才处理下一条：

```bash
guardedpy <<'TASKS'
解释分页函数的输入与输出。
/plan 检查记录数恰好是页大小整数倍时的处理。
TASKS
```

输出包含任务、流式回复和工具状态。除普通任务、`/plan`、`/review` 外，还可以使用 `/new`、`/conversations` 列表，以及 `/tests`、`/diff`、`/doctor`、`/permissions` 等本地检查。

调整设置时提供具体参数，例如 `/model deepseek-v4-pro`、`/effort max`；用 `/credentials status` 查看凭据状态。凭据录入、会话选择和删除、目标、排队、中断及审批决定在交互界面操作。纯文本调用遇到审批请求会结束，可以回到交互终端，通过 `/conversations` 打开这次会话并继续处理。

| 退出码 | 情况 |
| --- | --- |
| `0` | 正常处理完输入，或执行 `/exit` |
| `1` | 项目识别或凭据准备失败、回合失败或中断、需要审批，或在纯文本模式中使用 `/stop`、`/queue` |
| `2` | 命令行参数错误，或 `/plan` 缺少任务文本 |

本地检查通过文本报告结果。例如 `/tests` 检测到测试失败时，命令处理本身仍可返回 `0`。脚本需要 pytest 的退出状态时，直接运行 `python -m pytest`。
